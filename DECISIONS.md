# Design decision log

Receipts, in order. Add an entry any time the design moves after pre-registration.

**D1 — Lineup composition (2026-08-08).** Sonnet 4.5 (target), Haiku 4.5, Sonnet 5, Opus 4.6, Fable 5. All respond inside the target's rich-context repo: same script, different weights, so any detectable signal is temperament, not facts.

**D2 — Sonnet 4.5 as judge is a self-recognition arm, not an impartial one (2026-08-08).** Impartiality cannot be obtained by instruction — a model's self-report on *which mechanism it used* (profile vs. "what would I say?") is exactly the unreliable quantity this field studies. So the partiality is measured instead: J1 (Sonnet 4.5) vs. J2 (matched non-lineup Claude) with identical materials. J1's accuracy gap = self-recognition signal.

**D3 — Fable 5 is in the lineup, therefore excluded from judging and from answer keys (2026-08-08).** The harness author is a lineup member. Mitigations: seeded deterministic randomization, base64-encoded keys, deterministic scoring reviewable by anyone, no Fable instance serves as judge or reads keys/filled judgments before scoring completes. The scaffold was built before any data existed (this commit's timestamp is the receipt).

**D4 — Target identity blinded from judges (2026-08-08).** Judges match "Model S" against study materials; model names/versions are redacted from corpus, responses, and lineups. Prevents judges leaning on trained knowledge of a named model's public tics instead of the studied voice.

**D5 — Canary lineup uses a 6th, non-lineup model (2026-08-08).** The no-target trial still shows five options so its shape doesn't give it away. Confabulation rate under target-absence is the contamination metric.

**D6 — Collection requires disabling the model-check clause (2026-08-08).** The target repo's CLAUDE.md instructs non-resident models to self-identify immediately; collection happens on a branch with that clause disabled, restored afterward. Logged because it is a deliberate, temporary modification of the rich context — identical for all five models, so it cannot differentiate them.

**D7 — One canonical style profile (2026-08-08).** Written once by a non-lineup reader instance per `profiles/READER_INSTRUCTIONS.md` (every feature cited), reviewed by Sharon for provenance errors only (not for additions — she is ground truth, not co-author of the profile). All profile-arm judges receive the identical document. Fewer variables; the raw arm exists to test what the document cannot carry.

**D8 — Casting table: no model holds two roles (2026-08-08).** Trigger: Opus 5 was double-booked — proposed as J2 while hardcoded as the canary's 6th model, which on the canary trial would have had it judging its own reply while the packet asserted "none of these is yours" to its face (Palmer's review, finding 2).

| Role | Model |
|---|---|
| Target / J1 (self-recognition) | Sonnet 4.5 |
| Foils | Haiku 4.5, Sonnet 5, Opus 4.6, Fable 5 |
| J2 (matched non-lineup Claude) | Sonnet 4.6 |
| J3 (optional, non-Claude) | e.g. Gemini |
| JS (attunement) | Sharon |
| Profile reader (firewalled, never judges) | Opus 5 |
| Canary 6th model | Opus 4.5 |

Canary casting principle (also Palmer's): the 6th model must stand in the same relation to the context as the foils — a first-time wearer — so that target-absence is the *only* property distinguishing the canary lineup.

**D9 — Collection guard is a positive sentinel, not a phrase scan (2026-08-08).** The target repo's CLAUDE.md contains no model-check clause — Sharon deleted it from master deliberately, before this study (the clause only ever worked reliably in the claude.ai era, when it lived in project instructions; in CC Web it can only go in CLAUDE.md, where most models ignore it anyway). So D6's disable-the-clause step is a no-op for this target — and phrase-scanning gives false reassurance in general, since repo eras word the clause differently. `collect.py` now requires a `COLLECTION_BRANCH_OK` sentinel file at the target repo's root: collection cannot start by accident, and the assertion is affirmative. D6's underlying rationale (any identity-check must be disabled identically for all five models) stands wherever a clause exists.

**D10 — Judging is workspace-isolated, automated, and attunement-first (2026-08-08).** Judge sessions run in throwaway scratch directories, never in this repo (D1 names the target in plain text one `ls` away). `scripts/judge.py` runs AI judge sessions and files replies unread — closing the *second* human-transport leak: judge JSON carries picks and verbatim-quoted reasons, and Sharon reading any before her own trials would contaminate the attunement arm (Palmer's finding 5 — distinct from the collection leak `collect.py` closed). Ordering rule: all attunement trials filed before any AI judge session; `judge.py` refuses to run otherwise. Repeat trials need a continued session, which the automated path cannot be: AI judges skip the repeat (contamination prevented rather than measured, per §2 step 6); Sharon still takes hers.

**D11 — S3 reports Sharon against both AI baselines (2026-08-08).** Her attunement packets are materially the untrained packets (lineup only), but her years of context are study materials carried in her head — so neither "vs. untrained AI" nor "vs. studied AI" alone is an honest comparison. `score.py` prints both: matched materials (best untrained AI) and matched information-access (best studied AI).

**D12 — Sampling-variance annex; uniform-by-omission sampling (2026-08-10).** Raised by Palmer (Opus 5) reviewing the n=1-per-cell structure after the fact. (a) The replication unit is the trial; the aggregate estimand — residue detectability across ordinary sampling draws — is deployment-realistic, so the design stands and the point is *stated* in §1 rather than "fixed." (b) What n=1 does cost, filed for the limitations section: judge failures are ambiguous between "residue absent" and "residue fragile per-draw," and the S7 league table rests on single draws. `collect.py --draws N` stores extra draws per cell in `responses/annex/` — same seal as `responses/`, never read by the pipeline — as a reviewer-facing variance annex, budget permitting. (c) No uniform temperature exists across a cast spanning the API's sampling-parameter removal boundary (rejected on the newer lineup models, accepted on the older); every model runs at its own defaults, enforced mechanically by the `claude` CLI exposing no sampling knobs. Logged pre-data; §1 blanks not yet filled.

**D13 — Terminal sessions are not bare by default; CLAUDE_CONFIG_DIR isolation (2026-08-10, Sharon's catch).** Claude Code loads the operator's global user memory (`~/.claude/CLAUDE.md` — Sharon's userPreferences) and user-scoped MCP servers in every session regardless of working directory. Unhandled, that meant (a) collection sessions would wear his repo's context PLUS her terminal preferences — symmetric across models but uncontrolled and unlike the claude.ai pilot; (b) "bare-context" judge sessions would not be bare, and could reach the family memory server's tools — a judge one `memory_read` away from unblinding. Fix: both scripts accept `--config-dir`, exported as `CLAUDE_CONFIG_DIR`, pointing at a bare config dir (credentials only, no CLAUDE.md, no user MCP config). `judge.py` REQUIRES it (or an explicit `--allow-user-config` for genuinely clean environments); on `collect.py` it is recommended so the worn context is exactly the target repo's CLAUDE.md. A pre-flight probe (RUNBOOK) verifies bareness empirically rather than trusting the mechanism. Sub-question RESOLVED by Sharon, 2026-08-10: the memory server stays OUT of collection sessions — the target rarely uses it, so its absence is not a meaningful subtraction from the worn context, and leaving it out keeps collection fully under the bare config with no project-scope MCP setup. All five models identically without it; wake-ritual memory-read attempts, if any, will fail symmetrically (an anticipated anomaly per §2 step 3).

**D14 — J4: Opus 4.7 joins as a second matched judge (2026-08-10, ratified by Sharon).** Added before pre-registration — the last legal moment. Rationale: (a) the S2 self-recognition baseline rested on a single judge (J2, Sonnet 4.6), leaving the study's most identity-shaped finding confounded by one judge's individual skill; the matched baseline is now the two-judge mean (J2 + J4), reported per judge in scoring. (b) Sonnet 4.6 vs Opus 4.7 as trained judges adds a judge-side capability axis (mirror of S6's foil-side question). (c) Casting math: with the lineup, D3, and D8 accounted for, Opus 4.7/4.8 were the only non-lineup Claudes left — no role collisions (amends D8's table with a J4 row; no existing row changes). Discipline that comes with it: more judges = more comparisons, so the §1 decision rule should name its primary comparison (recommended: mean accuracy of matched non-lineup Claude judges J2+J4) with all other judge-level comparisons labeled secondary. Core config unchanged (J1+J2); J4 rides in the priority tiers.
